# 局域网狼人杀 MVP 技术架构

## 1. 技术栈

| 模块 | 技术 |
| --- | --- |
| 语言 | TypeScript |
| 前端 | React + Vite |
| 服务端 | Node.js + Fastify |
| 实时通信 | Socket.IO |
| 运行时验证 | Zod |
| 二维码 | qrcode |
| 本地持久化 | SQLite |
| 单元与集成测试 | Vitest |
| 浏览器自动化 | Playwright |
| 包管理与工作区 | pnpm workspace |

## 2. 目标平台

- 主机：Windows。
- 电脑浏览器：Chrome、Edge。
- 手机浏览器：Android Chrome、iPhone Safari、微信内置浏览器。
- 初期通过开发命令启动。
- MVP 完成后打包为 Windows 可执行程序，最终用户不需要安装 Node.js。

## 3. 工程结构

```text
game/
├─ apps/
│  ├─ web/                 # 手机玩家端和主机公共页面
│  └─ server/              # HTTP、Socket.IO、房间及游戏规则
├─ packages/
│  └─ shared/              # 共享类型、事件协议和 Zod Schema
├─ docs/
├─ package.json
└─ pnpm-workspace.yaml
```

## 4. 系统职责

### 4.1 Web 前端

- 渲染主机公共页面和玩家手机页面。
- 提交玩家操作意图。
- 展示服务端下发的授权视图。
- 合并实时聊天事件，按消息 ID 去重并按服务端序列排序。
- 保存本机重连凭证。
- 根据服务端截止时间显示倒计时。
- 不自行决定身份、死亡、投票结果或胜负。

### 4.2 服务端

- 创建并管理唯一房间。
- 识别连接对应的主机或玩家。
- 保存权威游戏状态。
- 执行身份分配、阶段切换、行动验证、结算和胜负判断。
- 为主机和每名玩家生成不同的安全视图。
- 管理倒计时、暂停、超时和断线状态。
- 保存关键快照和对局事件。
- 裁决聊天频道、发送资格、接收者和消息序列。
- 管理机器人适配器生命周期，并将机器人 Intent 交给绑定座位身份的动作执行器。

### 4.3 Shared 包

- 定义稳定的玩家、房间、阶段和行动类型。
- 定义 Socket.IO 事件载荷。
- 定义 `ChatMessage`、频道、发送者、内容和发送请求 Schema。
- 定义 `controller`、`botKind`、`BotIntent` 和主持人添加机器人请求 Schema。
- 提供前后端共用的 Zod Schema。
- 不包含依赖浏览器或服务端运行环境的业务实现。

## 5. 核心架构原则

1. 服务端是唯一权威状态源。
2. 客户端只能提交操作意图，不能提交或修改最终结果。
3. 昵称不作为身份凭证，玩家使用稳定的 `playerId`。
4. 重连使用高强度随机令牌，服务端只保存令牌哈希。
5. 完整游戏状态不得广播给客户端。
6. 主机视图、玩家公开视图和玩家私密视图必须分别生成。
7. Socket.IO 处理器只负责输入验证、会话识别和调用领域逻辑。
8. 游戏规则、结算和胜负判断实现为可独立测试的普通函数。
9. 所有随机操作在服务端执行。
10. 所有阶段由服务端状态机推进。
11. 倒计时以服务端保存的截止时间为准。
12. 所有客户端输入必须经过 Zod 运行时验证。
13. 所有操作必须验证阶段、身份、生存状态、目标和截止时间。
14. 操作使用唯一 `actionId`，避免断线重发导致重复执行。
15. 聊天接收者只能由服务端根据频道和玩家状态计算，客户端不能声明可见范围。
16. 机器人适配器只能接收自身座位的 `PlayerLobbyView`，不能接收 `LobbyRoom`、运行时、主持人视图、凭证或其他玩家视图。
17. 机器人 actor 由执行器调用参数绑定；`BotIntent` 不包含 actor 字段，并复用现有玩家动作 Schema 与房间方法。

## 6. 聊天模型

- `day-public`：所有玩家和主机可读。`ordered` 模式下仅当前白天发言者可发；`open` 模式下 `day-speech` 阶段所有存活且未离场玩家可发。
- `wolf-private`：仅狼人阶段的存活狼人可读写，主机和其他玩家载荷不得包含。
- `system`：仅服务端可生成，客户端请求 Schema 不接受该频道。
- `ChatMessage` 包含稳定 `id`、全局递增 `sequence`、天数、阶段、发送者快照、内容和服务端时间。
- `last-words` 不受自由讨论模式影响，始终只有当前遗言者可发送。
- `publicChat.canSend` 表示该座位在当前房间阶段和聊天模式下的资格；客户端还必须结合连接状态和公共阶段时钟，服务端会再次执行完整授权。

## 7. 状态与持久化

### 7.1 内存状态

运行中的房间和游戏状态保存在服务端内存中，以保证实现简单和实时响应。

聊天使用 SQLite 中的规范化 `game_sessions` 和 `chat_messages` 表保存。会话记录房间、角色配置、聊天模式、开始/结束时间和结果；消息记录唯一 ID、会话内递增序列、频道、阶段、发送者快照与内容。

消息持久化成功后才更新内存和广播。服务重启恢复时从消息表加载最近记录；旧快照内的聊天数组可一次性导入规范化表。`chat:history` 使用 `afterSequence` 分页补发，服务端根据读取者上下文裁剪频道，客户端可从序列 0 加载当前对局公开复盘。

### 7.2 SQLite 快照

关键状态同时写入 SQLite，用于主机程序意外退出后的恢复。至少在以下节点保存：

- 房间和玩家变化。
- 身份分配和确认。
- 阶段切换。
- 夜间行动提交和结算。
- 投票提交和放逐结算。
- 主机干预。
- 游戏结束。

服务重启恢复未结束对局时默认暂停，由主机确认后继续，避免停机期间的计时器直接触发结算。

## 8. 断线重连

玩家首次加入后获得：

- `roomId`
- `playerId`
- `reconnectToken`

浏览器将凭证保存在 `localStorage`。重新连接时由服务端验证令牌并恢复原玩家状态。

要求：

- 断线不删除玩家。
- 刷新、误关页面和锁屏后自动尝试恢复。
- 同一玩家只能有一个有效操作连接。
- 新设备接管必须经主机批准。
- 接管后旧凭证失效。
- 离线、死亡和离场是三个独立状态。
- 重连响应只包含该座位有权读取的公开聊天和狼人私聊。
- 机器人没有重连凭证，不能走玩家重连或设备接管流程。
- 快照恢复后机器人座位保持在线并重新交给 `BotManager` 驱动；人类座位仍按断线恢复规则处理。

## 9. 实时通信约定

事件名称使用统一命名风格。建议基础事件：

客户端发送：

```text
room:create
player:join
player:reconnect
player:confirm-role
game:start
game:submit-action
game:end-speaking
game:submit-vote
chat:send
chat:history
host:add-bot
host:update-chat-mode
host:pause
host:resume
host:skip-phase
host:update-timing
```

服务端发送：

```text
room:state
host:state
player:state
game:phase-changed
game:action-result
game:error
chat:message
player:connection-changed
```

具体载荷在实现对应里程碑时写入 `packages/shared`，并由 Zod Schema 约束。不得为同类角色操作随意新增不一致的协议风格。

## 10. 信息隔离

- 公共屏幕不得收到任何玩家身份、狼人目标、查验结果或女巫选择。
- 普通玩家不得收到其他玩家身份。
- 狼人只额外收到当前合法狼人队友及狼人阶段私密信息。
- 预言家查验结果只发送给预言家本人。
- 女巫刀口和药物状态只发送给女巫本人。
- 死亡玩家只能收到公共信息。
- 主持人、非狼人和死亡狼人不得收到 `wolf-private` 消息或历史。
- 机器人只获得其座位对应的 `PlayerLobbyView`；狼人机器人可见合法狼人私有字段，好人机器人与主持人不可见。
- 游戏结束后才允许公开全部身份和完整复盘。
- 测试必须直接检查网络载荷，不能只检查页面是否隐藏字段。

## 11. 时间管理

- 服务端保存每个阶段的绝对截止时间。
- 客户端根据截止时间显示剩余时间。
- 服务端决定真正超时和阶段推进。
- 暂停时记录剩余时间并取消当前定时任务。
- 恢复时使用剩余时间生成新的截止时间。
- 动态调整时间和主机延时必须广播公开结果并记录事件。

## 12. 测试策略

### 12.1 单元测试

使用 Vitest 覆盖：

- 身份分配。
- 阶段转换。
- 狼人投票与平票空刀。
- 女巫解药和毒药。
- 预言家查验。
- 夜间统一结算。
- 白天投票和放逐。
- 屠边与平局判断。
- 主机跳过和状态修正。
- 聊天 Schema、序列、限流、阶段授权和快照恢复。
- SQLite 迁移、游标分页、读取者授权和公开复盘。
- 机器人 Intent Schema、超时、取消、过期 revision、异常隔离和确定性整局推进。

### 12.2 服务端集成测试

使用多个虚拟 Socket.IO 客户端模拟主机和玩家，覆盖：

- 创建、加入和开始房间。
- 私密消息路由。
- 狼人聊天与确认。
- 非法身份和非法阶段操作。
- 掉线、重连和设备接管。
- 重复行动和超时。
- 一整局游戏流程。
- 公开聊天广播、狼人私聊定向发送和重连历史隔离。
- 主持人添加机器人权限、机器人视图隔离及机器人动作复用现有授权。

### 12.3 浏览器端到端测试

使用 Playwright 创建多个独立浏览器上下文，模拟主机和多名玩家，覆盖扫码链接后的主要用户流程及完整对局。

### 12.4 信息泄露测试

必须验证主机、普通玩家、狼人、预言家、女巫和死亡玩家收到的数据中不存在无权查看的信息。

### 12.5 真实设备验收

每个大里程碑结束后，使用 Windows 主机、Android 手机和 iPhone 验证：

- 二维码和局域网访问。
- Windows 防火墙行为。
- 手机浏览器兼容性。
- 锁屏、切后台和短暂断网恢复。

日常开发不依赖多台真实设备，主要依靠单元测试、虚拟客户端和 Playwright。

## 13. AI 玩家执行边界

- `LobbyPlayer.controller` 标记 `human` 或 `bot`，`botKind` 当前仅支持 `deterministic`。
- `BotAdapter.onView` 每次只接收对应座位的 `PlayerLobbyView`，以及包含 `playerId`、`revision`、截止时间和 `AbortSignal` 的上下文。
- `BotManager` 对每个机器人只保留一个在途决策；视图 revision 变化、强制重评估、移除座位或关闭服务都会取消旧任务。
- 决策超时、适配器异常、格式错误、generation 不匹配或 revision 过期时不执行 Intent，也不阻塞房间状态机。
- `executeBotIntent` 以调用参数绑定 actor，确认座位仍是机器人，并使用现有动作 Schema 和 `LobbyRoom` 方法执行。
- 当前 `DeterministicBotAdapter` 只用于本地自动化与基础占位，不调用外部模型供应商。外部模型接入需要另行设计重试、成本、内容安全和供应商配置。

## 14. 开发约束

- 开发前阅读相关文档。
- 不自行扩大 MVP 范围。
- 规则存在歧义时停止并询问，不自行决定。
- 新依赖必须说明必要性，优先使用现有依赖。
- 不通过删除、跳过或弱化测试解决失败。
- 每个任务完成后运行类型检查、测试和构建。
- 不提前实现账户、卡片、云服务、警长或扩展角色。
