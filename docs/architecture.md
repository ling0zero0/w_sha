# 局域网狼人杀 MVP 技术架构

## 1. 技术栈

| 模块 | 技术 |
| --- | --- |
| 语言 | TypeScript |
| 前端 | React + Vite |
| 服务端 | Node.js + Fastify |
| 实时通信 | Socket.IO |
| 运行时验证 | Zod |
| 二维码 | qrcode |
| 本地持久化 | SQLite |
| 单元与集成测试 | Vitest |
| 浏览器自动化 | Playwright |
| 包管理与工作区 | pnpm workspace |

## 2. 目标平台

- 主机：Windows。
- 电脑浏览器：Chrome、Edge。
- 手机浏览器：Android Chrome、iPhone Safari、微信内置浏览器。
- 初期通过开发命令启动。
- MVP 完成后打包为 Windows 可执行程序，最终用户不需要安装 Node.js。

## 3. 工程结构

```text
game/
├─ apps/
│  ├─ web/                 # 手机玩家端和主机公共页面
│  └─ server/              # HTTP、Socket.IO、房间及游戏规则
├─ packages/
│  └─ shared/              # 共享类型、事件协议和 Zod Schema
├─ docs/
├─ package.json
└─ pnpm-workspace.yaml
```

## 4. 系统职责

### 4.1 Web 前端

- 渲染主机公共页面和玩家手机页面。
- 提交玩家操作意图。
- 展示服务端下发的授权视图。
- 保存本机重连凭证。
- 根据服务端截止时间显示倒计时。
- 不自行决定身份、死亡、投票结果或胜负。

### 4.2 服务端

- 创建并管理唯一房间。
- 识别连接对应的主机或玩家。
- 保存权威游戏状态。
- 执行身份分配、阶段切换、行动验证、结算和胜负判断。
- 为主机和每名玩家生成不同的安全视图。
- 管理倒计时、暂停、超时和断线状态。
- 保存关键快照和对局事件。

### 4.3 Shared 包

- 定义稳定的玩家、房间、阶段和行动类型。
- 定义 Socket.IO 事件载荷。
- 提供前后端共用的 Zod Schema。
- 不包含依赖浏览器或服务端运行环境的业务实现。

## 5. 核心架构原则

1. 服务端是唯一权威状态源。
2. 客户端只能提交操作意图，不能提交或修改最终结果。
3. 昵称不作为身份凭证，玩家使用稳定的 `playerId`。
4. 重连使用高强度随机令牌，服务端只保存令牌哈希。
5. 完整游戏状态不得广播给客户端。
6. 主机视图、玩家公开视图和玩家私密视图必须分别生成。
7. Socket.IO 处理器只负责输入验证、会话识别和调用领域逻辑。
8. 游戏规则、结算和胜负判断实现为可独立测试的普通函数。
9. 所有随机操作在服务端执行。
10. 所有阶段由服务端状态机推进。
11. 倒计时以服务端保存的截止时间为准。
12. 所有客户端输入必须经过 Zod 运行时验证。
13. 所有操作必须验证阶段、身份、生存状态、目标和截止时间。
14. 操作使用唯一 `actionId`，避免断线重发导致重复执行。

## 6. 状态与持久化

### 6.1 内存状态

运行中的房间和游戏状态保存在服务端内存中，以保证实现简单和实时响应。

### 6.2 SQLite 快照

关键状态同时写入 SQLite，用于主机程序意外退出后的恢复。至少在以下节点保存：

- 房间和玩家变化。
- 身份分配和确认。
- 阶段切换。
- 夜间行动提交和结算。
- 投票提交和放逐结算。
- 主机干预。
- 游戏结束。

服务重启恢复未结束对局时默认暂停，由主机确认后继续，避免停机期间的计时器直接触发结算。

## 7. 断线重连

玩家首次加入后获得：

- `roomId`
- `playerId`
- `reconnectToken`

浏览器将凭证保存在 `localStorage`。重新连接时由服务端验证令牌并恢复原玩家状态。

要求：

- 断线不删除玩家。
- 刷新、误关页面和锁屏后自动尝试恢复。
- 同一玩家只能有一个有效操作连接。
- 新设备接管必须经主机批准。
- 接管后旧凭证失效。
- 离线、死亡和离场是三个独立状态。

## 8. 实时通信约定

事件名称使用统一命名风格。建议基础事件：

客户端发送：

```text
room:create
player:join
player:reconnect
player:confirm-role
game:start
game:submit-action
game:end-speaking
game:submit-vote
host:pause
host:resume
host:skip-phase
host:update-timing
```

服务端发送：

```text
room:state
host:state
player:state
game:phase-changed
game:action-result
game:error
player:connection-changed
```

具体载荷在实现对应里程碑时写入 `packages/shared`，并由 Zod Schema 约束。不得为同类角色操作随意新增不一致的协议风格。

## 9. 信息隔离

- 公共屏幕不得收到任何玩家身份、狼人目标、查验结果或女巫选择。
- 普通玩家不得收到其他玩家身份。
- 狼人只额外收到当前合法狼人队友及狼人阶段私密信息。
- 预言家查验结果只发送给预言家本人。
- 女巫刀口和药物状态只发送给女巫本人。
- 死亡玩家只能收到公共信息。
- 游戏结束后才允许公开全部身份和完整复盘。
- 测试必须直接检查网络载荷，不能只检查页面是否隐藏字段。

## 10. 时间管理

- 服务端保存每个阶段的绝对截止时间。
- 客户端根据截止时间显示剩余时间。
- 服务端决定真正超时和阶段推进。
- 暂停时记录剩余时间并取消当前定时任务。
- 恢复时使用剩余时间生成新的截止时间。
- 动态调整时间和主机延时必须广播公开结果并记录事件。

## 11. 测试策略

### 11.1 单元测试

使用 Vitest 覆盖：

- 身份分配。
- 阶段转换。
- 狼人投票与平票空刀。
- 女巫解药和毒药。
- 预言家查验。
- 夜间统一结算。
- 白天投票和放逐。
- 屠边与平局判断。
- 主机跳过和状态修正。

### 11.2 服务端集成测试

使用多个虚拟 Socket.IO 客户端模拟主机和玩家，覆盖：

- 创建、加入和开始房间。
- 私密消息路由。
- 狼人聊天与确认。
- 非法身份和非法阶段操作。
- 掉线、重连和设备接管。
- 重复行动和超时。
- 一整局游戏流程。

### 11.3 浏览器端到端测试

使用 Playwright 创建多个独立浏览器上下文，模拟主机和多名玩家，覆盖扫码链接后的主要用户流程及完整对局。

### 11.4 信息泄露测试

必须验证主机、普通玩家、狼人、预言家、女巫和死亡玩家收到的数据中不存在无权查看的信息。

### 11.5 真实设备验收

每个大里程碑结束后，使用 Windows 主机、Android 手机和 iPhone 验证：

- 二维码和局域网访问。
- Windows 防火墙行为。
- 手机浏览器兼容性。
- 锁屏、切后台和短暂断网恢复。

日常开发不依赖多台真实设备，主要依靠单元测试、虚拟客户端和 Playwright。

## 12. 开发约束

- 开发前阅读相关文档。
- 不自行扩大 MVP 范围。
- 规则存在歧义时停止并询问，不自行决定。
- 新依赖必须说明必要性，优先使用现有依赖。
- 不通过删除、跳过或弱化测试解决失败。
- 每个任务完成后运行类型检查、测试和构建。
- 不提前实现账户、卡片、云服务、警长或扩展角色。
