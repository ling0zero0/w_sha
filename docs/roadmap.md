# 局域网狼人杀 MVP 开发路线

## 1. 执行原则

- 每次只实施一个可独立验收的任务。
- 每个任务明确目标、范围、非目标、验收标准和验证命令。
- 每个阶段结束后必须通过类型检查、测试和生产构建。
- 游戏规则存在歧义时停止询问，不自行发明规则。
- 先完成基础玩法，再考虑高级角色和神秘卡片。
- 自动化测试负责日常验证，真实设备只用于里程碑验收。

## 2. 阶段 1：项目骨架

### 范围

- 创建 pnpm workspace。
- 建立 `apps/web`、`apps/server` 和 `packages/shared`。
- 配置 TypeScript、Vite、Fastify、Socket.IO、Zod、Vitest 和 Playwright。
- 建立统一的开发、类型检查、测试和构建命令。
- 添加基础错误处理和日志。

### 验收标准

- Web 和 Server 可以同时启动。
- 浏览器可打开基础主机页面和玩家页面。
- Shared 类型可被前后端引用。
- 基础测试能够运行。
- 类型检查和生产构建成功。

## 3. 阶段 2：局域网房间

### 范围

- 检测并选择主机局域网 IPv4 地址。
- 创建唯一房间、随机房间号和加入令牌。
- 主机显示二维码和加入地址。
- 玩家扫码后输入昵称加入。
- 实时同步玩家名单、编号和连接状态。
- 主机调整玩家顺序、移除玩家和刷新二维码。
- 实现重复昵称和非法令牌校验。

### 验收标准

- 多个虚拟客户端和至少两台真实手机可以加入。
- 玩家名单实时同步。
- 二维码使用局域网地址而非 `localhost`。
- 非法或已失效令牌不能加入。
- 同房间不能使用重复昵称。

## 4. 阶段 3：断线重连与主机控制

### 范围

- 为玩家签发随机重连令牌。
- 使用 `localStorage` 保存重连凭证。
- 支持刷新、误关页面、锁屏和短暂断网恢复。
- 实现在线、重连中、离线和离场状态。
- 支持主机批准新设备接管。
- 实现暂停、继续、时间调整和强制结束的基础框架。

### 验收标准

- 刷新后不会创建重复玩家。
- 不能只通过昵称冒充玩家。
- 新设备接管后旧设备失去操作权。
- 暂停和恢复后的剩余时间正确。
- 主机操作被公开提示并记录。

## 5. 阶段 4：身份配置与分配

### 范围

- 配置狼人、村民、预言家、女巫、守卫、猎人和白痴数量。
- 校验身份总数和最低阵营要求。
- 服务端随机分配身份。
- 玩家秘密查看和确认身份。
- 狼人查看狼人队友。
- 开局后关闭新玩家加入。
- 建立主机视图和玩家私密视图。

### 验收标准

- 每位玩家恰好获得一个身份。
- 身份数量与配置完全一致。
- 主机不能查看或指定身份。
- 普通玩家载荷中不包含其他身份。
- 狼人只能看到合法狼人队友。
- 全员确认或主机处理异常后进入第一夜。

## 6. 阶段 5：夜间核心

### 范围

- 狼人私密聊天、快捷消息和目标建议。
- 狼人目标、空刀、确认、改票和超时结算。
- 预言家查验。
- 女巫刀口、解药和毒药。
- 夜间阶段倒计时和主机跳过。
- 夜间统一结算和公开结果。

### 验收标准

- 仅存活狼人能访问狼人聊天。
- 狼人可合法自刀或刀队友。
- 最高票并列时空刀。
- 非对应身份不能提交角色行动。
- 女巫资源和自救规则正确。
- 私密信息只发送给有权限的玩家。
- 重复提交不会重复执行。

## 7. 阶段 6：白天流程

### 范围

- 天亮公布和平安夜提示。
- 第一夜死亡遗言和放逐遗言。
- 正反交替发言顺序。
- 发言倒计时、提前结束和离线跳过。
- 按当前发言者授权的白天公开文字和主机只读记录。
- 白天投票、弃票、改票和确认。
- 完整投票明细。
- 平票无人放逐。

### 验收标准

- 发言顺序符合编号和方向规则。
- 死亡或离场玩家自动跳过。
- 禁止自投，服务端同时校验。
- 投票期间不泄露票型。
- 投票结束后所有终端展示完整明细。
- 超时及离线玩家正确记为弃票。
- 非当前发言者、暂停状态和非发言阶段不能发送公开文字。
- 刷新或重连后恢复一致的本局公开记录。

## 8. 阶段 7：完整游戏循环

### 范围

- 昼夜循环。
- 屠边胜负判断。
- 同次结算双方达成条件时判定平局。
- 游戏结束时公开身份和对局记录。
- 主机强制结束记为“对局终止”。
- 再来一局和返回房间调整配置。
- 主机修正生死和离场处理。

### 验收标准

- 可以从扫码加入连续玩到游戏结束。
- 胜负判断优先于遗言和后续发言。
- 游戏结束后不能继续提交操作。
- 再来一局不残留旧身份、聊天、行动或投票。
- 主机修正后立即重新判断胜负。

## 9. 阶段 8：恢复、质量与发布

### 范围

- 使用 SQLite 保存关键快照和事件。
- 将聊天从快照内数组升级为规范化会话和消息表，支持游标补发与分页复盘。
- 服务重启后恢复未结束对局并默认暂停。
- 完善单元、Socket.IO 集成和 Playwright 测试。
- 完成信息泄露专项测试。
- 完成 Windows 打包和局域网使用说明。
- 进行 Android、iPhone 和微信内置浏览器验收。

### 验收标准

- 服务意外退出后可以恢复关键对局状态。
- 类型检查、所有测试和生产构建通过。
- 自动化测试能够模拟主机和多名玩家完成整局。
- 网络载荷不存在未经授权的身份或行动信息。
- Windows 用户无需安装 Node.js 即可启动。
- 真实设备可扫码加入、锁屏恢复并完成主要流程。

## 10. 阶段 9：聊天与 AI 扩展

详细拆分和验收标准见 `docs/chat-ai-roadmap.md`。

状态：截至 2026-07-19，功能实现与自动化测试已完成；真实双手机局域网验收尚未执行。

### 范围

- 收敛通用聊天领域模型和有序白天文字发言。
- 增加 SQLite 聊天历史、断线增量补发和对局复盘。
- 增加可配置的自由讨论模式。
- 建立只读取单一玩家授权视图的 AI 玩家适配器和测试 Bot。
- 使用 `controller` 和 `botKind` 区分人类与机器人座位。

### 验收标准

- 主机、普通玩家、死亡狼人和 AI 玩家均无法越权读取私密频道。
- 有序模式保持现有现场发言流程兼容。
- 服务重启和断线补发保持稳定序列，不重复、不漏发。
- AI 动作复用玩家动作校验，阶段切换可取消过期调用。
- AI actor 由执行器绑定，适配器只接收自身 `PlayerLobbyView`。
- 超时、取消、异常和过期 revision 不会执行机器人 Intent。

### 已交付边界

- 聊天记录存入规范化 SQLite 会话和消息表，支持授权游标补发、分页加载和公开复盘。
- `ordered` 保持轮流发言，`open` 允许白天发言阶段的存活玩家共同发送公开文字；遗言仍按当前发言者限制。
- 确定性本地机器人可完成身份确认、夜间行动、公开发言和白天投票。
- 机器人不能重连或被设备接管，快照恢复后保持在线并继续由管理器驱动。
- 当前未接入外部模型供应商；外部模型的成本、内容安全、重试和配置不属于本阶段交付。

## 11. 阶段 10：基础扩展角色

### 范围

- 加入守卫夜间守护、空守和不可连续守护同一玩家规则。
- 加入猎人夜死或放逐后开枪，以及毒死不可开枪规则。
- 加入白痴首次被放逐时翻牌免死和永久失去投票权规则。
- 扩展角色配置、共享契约、快照恢复、主机与玩家界面。
- 在正式人物画像缺失时使用稳定的空画像占位。

### 验收标准

- 新角色均受服务端身份和阶段权限校验。
- 守护目标、猎人候选和其他私密行动不会泄露到公共载荷。
- 猎人技能处理完成后才判断胜负和继续流程。
- 白痴翻牌状态跨昼夜及服务重启恢复。
- 旧四角色配置和旧房间快照保持兼容。

## 12. 每个任务的标准模板

```markdown
## 任务名称

### 目标
本任务要交付的单一结果。

### 范围
- 允许实现和修改的内容。

### 不做
- 本任务明确排除的内容。

### 验收标准
- 可观察、可测试的完成条件。

### 验证
- 类型检查命令。
- 单元或集成测试命令。
- 生产构建命令。
```

## 13. 长时间自动开发停止条件

遇到以下情况必须停止并询问：

- 文档规则存在冲突或歧义。
- 需要新增重大依赖或改变技术栈。
- 现有实现与安全边界冲突。
- 发现身份或夜间信息可能泄露。
- 需要改变 MVP 范围。
- 需要破坏性修改持久化数据。
- 测试持续不稳定且无法确定原因。

## 14. MVP 完成定义

只有同时满足以下条件才视为 MVP 完成：

- 所有阶段功能和验收标准完成。
- 类型检查、单元测试、集成测试、端到端测试和构建全部通过。
- 完成一整局自动化测试。
- 完成 Windows、Android 和 iPhone 的真实设备验收。
- 已确认公共屏幕和所有玩家视图不存在私密信息泄露。
- 已提供 Windows 启动及局域网故障排查说明。
