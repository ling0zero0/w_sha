# 局域网狼人杀 MVP 开发路线

## 1. 执行原则

- 每次只实施一个可独立验收的任务。
- 每个任务明确目标、范围、非目标、验收标准和验证命令。
- 每个阶段结束后必须通过类型检查、测试和生产构建。
- 游戏规则存在歧义时停止询问，不自行发明规则。
- 先完成基础玩法，再考虑高级角色和神秘卡片。
- 自动化测试负责日常验证，真实设备只用于里程碑验收。

## 2. 阶段 1：项目骨架

### 范围

- 创建 pnpm workspace。
- 建立 `apps/web`、`apps/server` 和 `packages/shared`。
- 配置 TypeScript、Vite、Fastify、Socket.IO、Zod、Vitest 和 Playwright。
- 建立统一的开发、类型检查、测试和构建命令。
- 添加基础错误处理和日志。

### 验收标准

- Web 和 Server 可以同时启动。
- 浏览器可打开基础主机页面和玩家页面。
- Shared 类型可被前后端引用。
- 基础测试能够运行。
- 类型检查和生产构建成功。

## 3. 阶段 2：局域网房间

### 范围

- 检测并选择主机局域网 IPv4 地址。
- 创建唯一房间、随机房间号和加入令牌。
- 主机显示二维码和加入地址。
- 玩家扫码后输入昵称加入。
- 实时同步玩家名单、编号和连接状态。
- 主机调整玩家顺序、移除玩家和刷新二维码。
- 实现重复昵称和非法令牌校验。

### 验收标准

- 多个虚拟客户端和至少两台真实手机可以加入。
- 玩家名单实时同步。
- 二维码使用局域网地址而非 `localhost`。
- 非法或已失效令牌不能加入。
- 同房间不能使用重复昵称。

## 4. 阶段 3：断线重连与主机控制

### 范围

- 为玩家签发随机重连令牌。
- 使用 `localStorage` 保存重连凭证。
- 支持刷新、误关页面、锁屏和短暂断网恢复。
- 实现在线、重连中、离线和离场状态。
- 支持主机批准新设备接管。
- 实现暂停、继续、时间调整和强制结束的基础框架。

### 验收标准

- 刷新后不会创建重复玩家。
- 不能只通过昵称冒充玩家。
- 新设备接管后旧设备失去操作权。
- 暂停和恢复后的剩余时间正确。
- 主机操作被公开提示并记录。

## 5. 阶段 4：身份配置与分配

### 范围

- 配置狼人、村民、预言家和女巫数量。
- 校验身份总数和最低阵营要求。
- 服务端随机分配身份。
- 玩家秘密查看和确认身份。
- 狼人查看狼人队友。
- 开局后关闭新玩家加入。
- 建立主机视图和玩家私密视图。

### 验收标准

- 每位玩家恰好获得一个身份。
- 身份数量与配置完全一致。
- 主机不能查看或指定身份。
- 普通玩家载荷中不包含其他身份。
- 狼人只能看到合法狼人队友。
- 全员确认或主机处理异常后进入第一夜。

## 6. 阶段 5：夜间核心

### 范围

- 狼人私密聊天、快捷消息和目标建议。
- 狼人目标、空刀、确认、改票和超时结算。
- 预言家查验。
- 女巫刀口、解药和毒药。
- 夜间阶段倒计时和主机跳过。
- 夜间统一结算和公开结果。

### 验收标准

- 仅存活狼人能访问狼人聊天。
- 狼人可合法自刀或刀队友。
- 最高票并列时空刀。
- 非对应身份不能提交角色行动。
- 女巫资源和自救规则正确。
- 私密信息只发送给有权限的玩家。
- 重复提交不会重复执行。

## 7. 阶段 6：白天流程

### 范围

- 天亮公布和平安夜提示。
- 第一夜死亡遗言和放逐遗言。
- 正反交替发言顺序。
- 发言倒计时、提前结束和离线跳过。
- 白天投票、弃票、改票和确认。
- 完整投票明细。
- 平票无人放逐。

### 验收标准

- 发言顺序符合编号和方向规则。
- 死亡或离场玩家自动跳过。
- 禁止自投，服务端同时校验。
- 投票期间不泄露票型。
- 投票结束后所有终端展示完整明细。
- 超时及离线玩家正确记为弃票。

## 8. 阶段 7：完整游戏循环

### 范围

- 昼夜循环。
- 屠边胜负判断。
- 同次结算双方达成条件时判定平局。
- 游戏结束时公开身份和对局记录。
- 主机强制结束记为“对局终止”。
- 再来一局和返回房间调整配置。
- 主机修正生死和离场处理。

### 验收标准

- 可以从扫码加入连续玩到游戏结束。
- 胜负判断优先于遗言和后续发言。
- 游戏结束后不能继续提交操作。
- 再来一局不残留旧身份、聊天、行动或投票。
- 主机修正后立即重新判断胜负。

## 9. 阶段 8：恢复、质量与发布

### 范围

- 使用 SQLite 保存关键快照和事件。
- 服务重启后恢复未结束对局并默认暂停。
- 完善单元、Socket.IO 集成和 Playwright 测试。
- 完成信息泄露专项测试。
- 完成 Windows 打包和局域网使用说明。
- 进行 Android、iPhone 和微信内置浏览器验收。

### 验收标准

- 服务意外退出后可以恢复关键对局状态。
- 类型检查、所有测试和生产构建通过。
- 自动化测试能够模拟主机和多名玩家完成整局。
- 网络载荷不存在未经授权的身份或行动信息。
- Windows 用户无需安装 Node.js 即可启动。
- 真实设备可扫码加入、锁屏恢复并完成主要流程。

## 10. 每个任务的标准模板

```markdown
## 任务名称

### 目标
本任务要交付的单一结果。

### 范围
- 允许实现和修改的内容。

### 不做
- 本任务明确排除的内容。

### 验收标准
- 可观察、可测试的完成条件。

### 验证
- 类型检查命令。
- 单元或集成测试命令。
- 生产构建命令。
```

## 11. 长时间自动开发停止条件

遇到以下情况必须停止并询问：

- 文档规则存在冲突或歧义。
- 需要新增重大依赖或改变技术栈。
- 现有实现与安全边界冲突。
- 发现身份或夜间信息可能泄露。
- 需要改变 MVP 范围。
- 需要破坏性修改持久化数据。
- 测试持续不稳定且无法确定原因。

## 12. MVP 完成定义

只有同时满足以下条件才视为 MVP 完成：

- 所有阶段功能和验收标准完成。
- 类型检查、单元测试、集成测试、端到端测试和构建全部通过。
- 完成一整局自动化测试。
- 完成 Windows、Android 和 iPhone 的真实设备验收。
- 已确认公共屏幕和所有玩家视图不存在私密信息泄露。
- 已提供 Windows 启动及局域网故障排查说明。
