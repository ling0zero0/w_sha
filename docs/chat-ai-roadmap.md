# 聊天与 AI 玩家开发路线

## 1. 目标与原则

本路线在不改变现有现场发言玩法的前提下，逐步加入白天文字聊天、聊天历史、自由讨论和 AI 玩家。

- 服务端是聊天权限、可见范围和动作合法性的唯一裁决者。
- 玩家、机器人和系统消息使用同一消息信封，具体频道决定可见范围。
- 机器人只能读取对应座位的 `PlayerLobbyView`，不能直接读取房间内部状态。
- 每个阶段必须同时完成共享协议、服务端、界面、测试和文档。
- 任一公开或主持人载荷不得包含狼人私聊、隐藏身份或未公开行动。
- 每个阶段独立交付；SQLite、自由讨论和 AI 玩家不并行修改核心状态机。

- 确定性机器人可自动确认身份、执行夜间行动、发送公开消息、结束发言和完成白天投票；服务端测试覆盖全机器人对局推进至结束。

当前未接入任何外部大模型或聊天机器人供应商。真实 Windows 主机加两台手机的局域网验收仍需在具备实体设备时人工执行，不能以自动化测试结果替代。

## 3. 阶段 1：通用聊天领域模型

### 范围

- 在 `packages/shared` 固化频道、发送者、内容和消息信封 Schema。
- 使用全局单调 `sequence` 和稳定消息 `id` 支持排序与去重。
- 将狼人私聊迁移到通用消息模型。
- 明确频道接收者选择和服务端信息裁剪规则。
- 为旧快照中的狼人消息提供一次性兼容迁移。

### 验收标准

- 所有跨边界消息均通过 Zod 校验。
- 主持人、非狼人和死亡狼人看不到 `wolf-private` 消息。
- 旧快照可恢复为新消息结构。
- 新一局清空上一局消息和序列状态。
- Shared、Room、Runtime 和 Socket 测试覆盖协议与隔离边界。

## 4. 阶段 2：有序白天文字聊天

### 范围

- `last-words` 和 `day-speech` 阶段仅当前发言者可发送公开文字。
- 所有玩家和主持人可读取本局公开消息。
- 死亡玩家仅能在自己的遗言轮次发送。
- 暂停、投票、结算、夜间和游戏结束阶段禁止发送公开文字。
- 客户端按 `sequence` 增量合并、去重并自动滚动。
- 重连后通过玩家或主持人视图恢复本局公开历史。

### 验收标准

- 当前发言者发送成功，非当前发言者得到明确错误。
- 暂停后发送失败，恢复后阶段和轮次资格继续生效。`publicChat.canSend` 只表达房间阶段和当前发言者资格，暂停状态由公共时钟叠加，并由服务端最终拒绝。
- 重复事件不会产生重复消息，乱序事件按 `sequence` 排列。
- 狼人私聊事件仅发送给仍存活的狼人连接。
- 主持人和玩家刷新或重连后看到一致公开历史。
- 移动端输入区、只读记录和主持人记录在桌面与手机视口无重叠。

### 验证

- `corepack pnpm typecheck`
- `corepack pnpm test`
- `corepack pnpm build`
- Playwright 覆盖两名玩家、主持人、死亡玩家和狼人客户端。

## 5. 阶段 3：SQLite 历史、补发与复盘

### 数据模型

- `game_sessions`：对局 ID、房间号、开始/结束时间、规则版本、结果和归档状态。
- `chat_messages`：对局 ID、消息 ID、序列、频道、天数、阶段、发送者快照、内容 JSON 和创建时间。
- `chat_cursors` 不持久化到数据库；客户端使用最近已见 `sequence` 请求增量。

### 范围

- 从单行运行时快照中分离规范化聊天记录，同时保留快照用于崩溃恢复。
- 消息写入与内存状态更新保持确定顺序，失败时不广播未持久化消息。
- 增加按频道和 `afterSequence` 查询的重连补发接口。
- 增加分页历史查询和游戏结束后的公开复盘视图。
- 狼人私聊仅在游戏结束且产品规则明确允许时进入复盘；默认不公开。

### 验收标准

- 服务重启后可恢复当前对局聊天。
- 重连客户端只补发游标后的授权消息。
- 分页不重复、不漏消息，并保持稳定排序。
- 查询层始终要求接收者上下文，不能通过传入任意频道绕过授权。
- 数据库迁移可从现有 `runtime_snapshot` 平滑升级。

### 完成状态

已完成。消息先写入 SQLite，成功后才进入内存列表并广播；恢复时从规范化消息表加载最近消息。`chat:history` 只接受 `afterSequence` 和分页大小，读取权限由服务端根据主持人或当前玩家状态决定。主持人和玩家客户端可从序列 0 分页加载当前对局记录，并在游戏结束界面显示不包含狼人私聊的公开复盘。

## 6. 阶段 4：自由讨论模式

### 范围

- 在房间规则中加入 `ordered` 与 `open` 两种白天聊天模式。
- 主持人只能在开局前配置模式，进行中的对局不热切换。
- 自由讨论仅在允许的白天阶段开放给存活玩家。
- 保留暂停、限流、长度、连接状态和死亡状态校验。
- UI 显示当前模式，并在自由讨论时隐藏当前发言者专属输入限制。

### 验收标准

- 两种模式复用同一消息协议和持久化路径。
- 有序模式行为与阶段 2 完全兼容。
- 自由讨论下并发消息由服务端分配唯一递增序列。
- 死亡玩家、观察者和主持人不能伪装成玩家发送。
- 模式配置包含在快照、重连视图和复盘元数据中。

### 完成状态

已完成。主持人仅能在大厅切换模式；`open` 只放宽 `day-speech` 阶段的公开文字发送资格，允许所有存活且未离场玩家参与。`last-words` 仍严格限制为当前遗言者，暂停和其他阶段的限制保持不变。

## 7. 阶段 5：AI 玩家接口

### 接口边界

```ts
interface BotAdapter {
  readonly kind: BotKind;
  onView(view: PlayerLobbyView, context: BotTurnContext): Promise<BotIntent | null>;
  dispose(): Promise<void>;
}
```

- `BotTurnContext` 只包含座位 ID、视图 `revision`、截止时间和取消信号。
- `BotIntent` 使用现有玩家动作的判别联合，不直接修改房间状态。
- Bot 管理器将 Intent 送入现有玩家动作 Schema 和房间方法。
- Bot 占用正常玩家座位，拥有独立身份、存活状态和显示名称。

### 范围

- 增加 Bot 座位创建、启动、取消、超时和销毁生命周期。
- 每次状态变化只向 Bot 推送该座位授权后的 `PlayerLobbyView`。
- 增加确定性的测试 Bot，用于自动完成准备、夜间行动、发言和投票。
- 使用单 Bot 单次在途决策、超时、取消、generation 和 `revision` 校验拒绝过期结果。
- 第一版不直接接入外部模型服务。

### 验收标准

- Bot 无法读取主持人视图、其他玩家私有视图或房间内部字段。
- 非法、过期、重复或超时 Intent 由现有动作校验拒绝。
- 阶段切换会取消上一阶段尚未完成的 Bot 调用。
- Bot 异常不会阻塞房间状态机，主持人可以移除 Bot 座位。
- 测试证明狼人 Bot 能看见狼人信息，而好人 Bot 和主持人不能看见。

### 完成状态

已完成。`LobbyPlayer.controller` 为 `human | bot`，机器人座位使用 `botKind: "deterministic"`；旧快照缺失字段时默认按人类座位兼容。执行器通过闭包参数绑定 `playerId`，Intent 载荷不能声明或替换 actor，并再次使用现有动作 Schema 解析载荷。机器人不能使用玩家重连令牌，也不能被新设备申请接管；从快照恢复后机器人保持 `online` 并由管理器继续驱动，人类座位则按原恢复规则变为离线。当前只有无需网络和外部服务的确定性本地机器人。

## 8. 交付与分工

主执行者负责状态机、协议整合、冲突处理和最终验收。子智能体只承担边界明确且写集合不重叠的任务：

- 协议与 Schema 测试。
- Room 与 Socket.IO 授权测试。
- Web 组件测试和 Playwright 场景。
- SQLite 仓储层及迁移测试。
- AI 适配器测试实现和威胁模型审查。

每个子任务合并前必须由主执行者复查信息隔离、错误码、快照兼容和测试覆盖。
